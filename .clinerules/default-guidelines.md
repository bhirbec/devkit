## Brief overview
This set of guidelines provides general preferences for software development collaboration. These are global guidelines that can be applied to any project and may be refined as we work together more.

## Communication style
- Prefer direct, concise communication focused on technical details
- Avoid unnecessary pleasantries at the beginning of messages
- Include reasoning behind technical decisions when making suggestions
- Use code examples to illustrate concepts when applicable

## Development workflow
- Start with planning and architecture before implementation
- Break down complex tasks into smaller, manageable steps
- Validate functionality incrementally rather than building everything at once
- Document key decisions and design patterns used in the project

## Coding best practices
- Follow language-specific conventions and best practices
- Use meaningful variable and function names that clearly indicate purpose
- Keep functions small and focused on a single responsibility
- Include appropriate comments for complex logic, but avoid commenting obvious code
- Prioritize readability and maintainability over clever solutions

## Project organization
- Organize files logically by feature or functionality
- Maintain a clear separation of concerns between different parts of the application
- Use consistent file naming conventions throughout the project
- Keep related files close together in the directory structure

## Testing approach
- Write tests for critical functionality
- Aim for a balance between test coverage and development speed
- Test edge cases and error handling scenarios
- Consider both unit tests and integration tests where appropriate
